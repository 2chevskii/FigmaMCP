# Установка

Для работы Figma MCP нужны сервер-компаньон, плагин Figma Bridge и MCP-клиент. Сервер работает локально и взаимодействует с Figma Desktop через плагин.

<LatestRelease />

## Установите компаньон

Версия и ссылки на файлы загружаются через [API последних выпусков GitHub](https://api.github.com/repos/2chevskii/FigmaMCP/releases/latest). Используйте показанную версию при настройке установки.

### Запуск через `dnx` без установки

Установите .NET 10 SDK. `dnx` загрузит указанную версию инструмента в кэш NuGet и запустит её без постоянной установки. Команда с версией и конфигурация MCP-клиента показаны выше.

### Установка как глобального инструмента .NET

Установите .NET 10, затем выполните команду с нужной версией, показанную выше. Команда глобальной установки загружает соответствующий выпуск из NuGet.org.

MCP-клиент запускает установленную команду `figma-mcp-server` как дочерний процесс.

### Использование автономного выпуска

Выберите архив сервера для своей платформы по ссылкам с версией выше.

Распакуйте архив и укажите исполняемый файл как команду MCP-сервера. В Windows используйте `FigmaMCP.exe`, в Linux и macOS — `FigmaMCP`. Для этих архивов установка .NET не требуется.

## Установите плагин Figma Bridge

Скачайте архив плагина по ссылке выше и распакуйте его. В Figma Desktop импортируйте извлечённый `manifest.json` как плагин для разработки, затем откройте плагин в нужном документе.

Оставьте порт Bridge равным `3846`, если сервер не запущен с другим портом. По умолчанию компаньон слушает `127.0.0.1:3846/bridge`. Если порт занят и порт явно не задан, сервер выберет следующий доступный порт и сообщит о нём в `stderr`; укажите этот порт в настройках плагина. Явное значение `--port <1-65535>` не меняется.

## Подключите MCP-клиент

Импортируйте файл [`mcp.json`](https://github.com/2chevskii/FigmaMCP/blob/master/mcp.json) в MCP-клиент, поддерживающий импорт конфигурации серверов:

```json
{
  "mcpServers": {
    "figma": {
      "command": "figma-mcp-server"
    }
  }
}
```

Для автономного выпуска укажите полный путь к исполняемому файлу. Например, в Windows:

```json
{
  "mcpServers": {
    "figma": {
      "command": "C:\\path\\to\\FigmaMCP.exe"
    }
  }
}
```

Если клиент не поддерживает импорт файла, добавьте эту конфигурацию в настройки MCP-серверов. Клиент запускает компаньон через STDIO; стандартный вывод процесса должен оставаться доступным для протокола MCP.

## Проверьте подключение

Запустите MCP-клиент и откройте плагин в документе Figma, затем вызовите `list_figma_connections`. Передавайте возвращённый `connection_id` инструментам, работающим с документом. Доступные операции и их требования описаны в [справочнике инструментов](./TOOLS).

Чтобы обновить установленный инструмент .NET, выполните `dotnet tool update --global FigmaMCP`. Для архивов выпуска используйте последние ссылки с версией выше; при необходимости обновите путь к исполняемому файлу в MCP-клиенте.
